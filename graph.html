Help: How to Use Floyd-Warshall Demo

Project Overview

This is an interactive implementation of the Floyd-Warshall algorithm for finding shortest paths between all pairs of vertices in a weighted directed graph.

How to Input Your Graph

  1. Set Number of Nodes:
    • Enter the number of vertices in your graph in the "Number of nodes" field
    • Click "Apply" to generate the input matrix
  2. Enter Matrix Values:
    • Fill the adjacency matrix with edge weights
    • Use "INF" or leave empty for no direct edge
    • Diagonal should be 0 (distance from a node to itself)
  3. Optional Settings:
    • Vertex names: Enter custom names separated by commas (e.g., A,B,C,D)
    • Edge type: Choose between directed or undirected graphs
    • Weight mode: Select weighted or unweighted edges
    • Allow negative: Toggle negative weight allowance

Running the Algorithm

  1. After entering your graph, click "Run Floyd-Warshall"
  2. The algorithm will generate:
    • Distance Matrix: Shows shortest path distances
    • Next Matrix: Used for path reconstruction
    • Graph Visualization: Visual representation of your graph

Understanding Results

  • Distance Matrix:
    • Each cell (i,j) shows the shortest distance from vertex i to j
    • Red cells indicate negative cycles (if present)
    • Gray "INF" cells mean no path exists
  • Finding Specific Paths:
    • Use the "From" and "To" dropdowns to select vertices
    • Click "Show Shortest Path" to highlight the path
    • The path and its total distance will be displayed

Additional Features

  • Random Graph: Generate a random graph for testing
  • Clear: Reset the input matrix
  • Import/Export:
    • Import matrix from .txt/.csv files
    • Export results to CSV format

Floyd-Warshall Algorithm Overview

The Floyd-Warshall algorithm is a dynamic programming approach for finding shortest paths between all pairs of vertices in a weighted graph, including graphs with negative edge weights (but no negative cycles).

Floyd–Warshall (Detailed DP Explanation)

This section contains a detailed dynamic-programming derivation and explanation of the Floyd–Warshall algorithm (adapted from course notes).

Problem: All Pairs Shortest Paths. Given a weighted graph G=(V,E,w) (weights may be negative but no negative cycles), compute the shortest-path distance between every ordered pair of vertices u,v in V.

Idea: Order the vertices arbitrarily as v1,v2,...,vn. Let M[i][j][k] be the length of the shortest path from vi to vj that is allowed to use only intermediate vertices from the set {v1,...,vk} (that is, vertices on the path other than the endpoints must come from that set). Our goal is M[i][j][n].

Base case: With k = 0 no intermediate vertices are allowed, so M[i][j][0] is simply the direct edge weight w(vi,vj) (or +INF if no edge). The diagonal M[i][i][0] = 0.

Recurrence: When adding vertex vk, either the shortest i→j path does not use vk, in which case the best length is M[i][j][k-1], or it does use vk, in which case the path splits as i→k concatenated with k→j where both subpaths only use vertices from {v1..vk-1}. Thus

M[i][j][k] = min( M[i][j][k-1], M[i][k][k-1] + M[k][j][k-1] )

By iterating k from 1..n and applying this update for all i,j we compute all-pairs shortest distances. This yields the classic O(n^3) time algorithm.

Algorithm (conceptual):

for i = 1..n:
  for j = 1..n:
    dist[i][j] = w(i,j)   # base (k = 0)

for k = 1..n:
  for i = 1..n:
    for j = 1..n:
      dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j])

Correctness sketch: Use induction on k. For each k, the DP value M[i][j][k] gives the shortest i→j path whose internal vertices lie in {v1..vk}. Either the true shortest such path avoids vk (handled by M[i][j][k-1]) or it uses vk and splits at vk into two optimal subpaths (handled by M[i][k][k-1] + M[k][j][k-1]). Taking the minimum covers both possibilities.

Complexity: Three nested loops over n give O(n^3) time. Space is O(n^2) if we maintain only the current distance matrix (we can overwrite in place).

Notes and example: Running the recurrence builds the distances progressively allowing more intermediate vertices; after k = n all possible intermediates are allowed and the matrix contains final shortest-path lengths. The algorithm also supports path reconstruction using a "next"/"via" matrix to remember intermediate choices.

Key Concepts

  • Dynamic Programming approach to find shortest paths between all pairs of vertices
  • Handles negative edge weights (but not negative cycles)
  • Time complexity: O(V³) where V is the number of vertices
  • Space complexity: O(V²) for storing the distance matrix
